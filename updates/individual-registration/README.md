## Что подключено

Индивидуальная запись для Короля корта, Americano + INDIVIDUAL, Тренировка + игра и Cancha Abierta. После выбора события: вход при необходимости → проверка актуальных данных, собственных записей и контакта → стоимость и условия → явное подтверждение → настоящий POST существующего API → CONFIRMED/WAITLIST из ответа → «Мои мероприятия» (заново читается существующий список сайта).

Защита: не передаётся ID игрока; Bearer-сессия из действующего клиента; cookie сайта не отправляются; нет автоматического повтора POST/PATCH. Двойное нажатие блокируется. Если изменились цена/валюта/условия/формат/дедлайн/переход в резерв, требуется повторная проверка и согласие. После потери ответа — сверка своей записи без новой отправки. Смена аккаунта отменяет старую проверку до мутации. Google возвращает к выбранному мероприятию, но не создаёт запись автоматически.

WhatsApp/Telegram можно добавить в приложении через действующий PATCH. При отсутствии уровня показывается needLevel и ссылка на профиль сайта. Это известная граница первого инкремента: безопасного отдельного JSON API изменения уровня пока нет. Парная регистрация и отмена участия в этот patch не входят; для парных событий остаётся сайт.

Форматы используют разные тексты: −10 только у Короля корта/индивидуального Americano; Cancha Abierta — собственные условия без турнирного штрафа; тренировка — условия отмены без штрафа за опоздание. Дедлайн берётся из события, при отсутствии — действующий стандарт сервера «начало минус 24 часа». Финансовые условия перед публикацией сверить с решением владельца и актуальным PR #652.

## Применение

Проверить patch и текущий master, затем:

    git apply --check individual-registration.patch
    git apply individual-registration.patch
    cd mobile-app
    pnpm install --frozen-lockfile
    pnpm test
    pnpm typecheck
    pnpm build:site

Включить в PR исходники, тесты, README и пересобранную src/main/resources/static/app/. Скрипт scripts/build-site.mjs восстановлен: package.json уже ссылался на него, но в базовом репозитории файла нет. Для локального HTTP-просмотра можно отдельно сделать pnpm exec expo export --platform web --output-dir dist-individual.

Перед реальными мутациями на проде пройти обычные проверки/деплой проекта и проверить сценарий на согласованном тестовом мероприятии. Не записывать владельца или других игроков в существующие настоящие игры для автоматической проверки.

## Контракт и границы

GET /api/public/tournaments/{id}; GET /api/players/me/tournaments; GET /api/players/me/contact-status; PATCH /api/players/me/contact; POST /players/tournaments/{id}/register. Статус/позиция берутся из JSON-ответа, needContact/needLevel и сообщение бизнес-отказа не теряются. 401 при мутации обновляет сессию, но не повторяет запрос; требуется новый явный шаг. 403 не объявляет игрока организатором автоматически.

У существующего сервера нет idempotency key и атомарной фиксации условий заявки: preflight снижает риск изменения цены, но не создаёт транзакционного quote. Результат неопределённого POST хранится в памяти текущей модели; после перезагрузки экран снова проверяет свою запись, а серверная уникальность защищает от второй регистрации. Приватные данные истории не используются для выдумывания её статуса. Без согласованного тестового аккаунта и мероприятия настоящий вход/запись end-to-end здесь не проверялись.

Ничего на сайт этим пакетом не опубликовано. Публикация выполняется обычным конвейером проекта после ревью.
