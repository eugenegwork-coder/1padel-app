# 1Padel.App: сохранение входа после закрытия

Подготовлено 19.10.2026 под UstinKO/padel-core-service main, базовая версия 0eb09b003d4c8de427113274f0f487ab425f67a8 (PR #645).

## Что изменено

- Только refresh-токен сохраняется в localStorage под отдельным ключом onepadel.app.refresh.v1. Access, пароль, профиль и мероприятия не сохраняются. Native SecureStore не меняется.
- Открытие новой вкладки/повторный запуск: refresh, загрузка настоящего профиля и личного календаря, без повторного Google/пароля.
- Выход очищает сохранённый вход; поздние ответы не могут восстановить его.
- При истёкшем refresh — повторный вход. При сетевом сбое токен сохраняется для повтора. При запрете хранилища — сообщение ошибки.
- HTTP Wi-Fi просмотр не читает и не пишет токены.
- Добавлен отсутствующий в main scripts/build-site.mjs: package.json уже ссылается на него, без него штатная пересборка не работает.
- Документация обновлена. Серверный API и механика Google не меняются.

## Как применить

Проверить содержимое remember-session.patch, затем в актуальном серверном репозитории:

    git apply --check remember-session.patch
    git apply remember-session.patch
    cd mobile-app
    pnpm install --frozen-lockfile
    pnpm test
    pnpm typecheck
    pnpm build:site

Коммитить исходники, тесты, документацию и новую сборку src/main/resources/static/app/; устаревший файл JS из предыдущей сборки удалить штатным build:site. Создать PR и пройти обычные проверки/деплой. Если main изменился, перенести смысл изменений с учётом текущего кода.

## Проверено локально

31/31 тест, включая 9 новых сценариев сохранения сессии; TypeScript — без ошибок; production web export под /app/ успешен. git apply --check проверен на исходной базовой версии. Тесты используют вымышленные аккаунты и токены; настоящих пользовательских данных в пакете нет.

Реальная проверка на iPhone после деплоя: войти Google, закрыть вкладку, открыть https://1-padel.com/app/, проверить Мои мероприятия; повторить с почтой; Выйти → закрыть/открыть → требуется вход. Временное отсутствие интернета не должно стирать вход. После обновления потребуется один новый вход, поскольку предыдущая версия сохраняла токены только в памяти уже закрытой вкладки.

## Границы

Срок refresh определяет сервер (по умолчанию 7 дней, успешный refresh выдаёт новый). Данные браузера/приватного сеанса могут быть очищены; разные браузеры и режимы установки могут иметь отдельное хранилище. localStorage доступен JS того же origin, это не HttpOnly-cookie. Для текущего клиента используется его действующий JWT-контракт без изменения серверной аутентификации.

Ничего не опубликовано на сервер сайта этим пакетом: публикация выполняется обычным конвейером проекта.
