# 1Padel.App — индивидуальная отмена записи

Подготовлено20.10.2026 поверх UstinKO/padel-core-service master `6d7f800df5da1aaf8af4ebcdb3cc83a08bc77640` (PR661).
Это готовое клиентское обновление для действующего приложения `/app/`; серверных Java-изменений нет.

## Что подключено

«Мои мероприятия» → «Отменить запись» → актуальная собственная запись, событие и условия →
необязательная причина → явное согласие → один настоящий POST существующего API →
подтверждение сайта → возврат к заново загруженному списку.

Четыре формата с INDIVIDUAL: King of Court, Americano, Padel Clinic, Cancha Abierta.
CONFIRMED и WAITLIST/WAITLIST_INVITED поддержаны. Пары остаются на сайте.
После успешной отмены запись не добавляется искусственно в историю: сервер не возвращает отменённые записи в historical.

Срок — индивидуальный deadlineCancelacion, по умолчанию начало минус24часа, строго раньше него.
Правило сервера одинаково для Cancha и резерва. После срока POST блокируется, предлагается связаться с организатором.
Для Cancha не копируются финансовые условия турниров. Для подтверждённых Clinic/King/Americano показано
фактическое правило сайта «менее24часов — полная оплата; возврат/освобождение при оплатившей замене».
Финансовые24часа и изменяемый технический срок самостоятельной отмены явно разделены.
Автоматический возврат денег не обещается; финансовая политика сервера не меняется.

Перед POST перечитываются детали и собственные регистрации; изменение статуса/даты/цены/условий/срока/registrationDate
требует повторного согласия. Смена аккаунта прерывает старый сценарий.
Двойное нажатие блокируется. При потерянном/непонятном ответе и401 нет автоматического повтора POST,
только сверка GET. Если запись всё ещё активна, повтор не разблокируется.

## Применение

Скачайте `individual-cancellation.patch` из этой папки. Проверьте изменения построчно и актуальный master.
Не заменяйте mobile-app старым архивом из корня репозитория eugenegwork-coder/1padel-app:
этот патч предназначен для mobile-app внутри актуального серверного репозитория после PR661.

```sh
git apply --check individual-cancellation.patch
git apply individual-cancellation.patch
cd mobile-app
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm build:site
```

Закоммитьте исходники, тесты, документацию и пересобранную `src/main/resources/static/app/`.
Полная сверка с исходниками сайта и ограничения включены в patch: `docs/mobile-individual-cancellation.md`.
Форма reason передаётся в POST `/players/tournaments/{id}/cancel` как application/x-www-form-urlencoded
(совместимо с действующим @RequestParam), не в URL; principal из Bearer, cookies/playerId не передаются.

  В нём только вымышленные данные, нет запросов к сайту.
- Настоящая отмена на production здесь не выполнялась. Запись заказчика на тренировку не изменялась.

Перед обычным деплоем конвейера проекта проверить реальную отмену на специально созданных тестовых игроке/мероприятии,
включая причину, обновление «Моих мероприятий», deadline-отказ и освобождение места с обработкой очереди.
Не отменять существующие реальные заявки заказчика/других игроков для автоматической проверки.

У сервера нет атомарной проверки версии записи/quote или idempotency key. Клиентский preflight уменьшает,
но не устраняет гонку GET→POST. Неопределённое состояние хранится только в памяти модели до полной перезагрузки.
Часы устройства определяют предварительную доступность; окончательное решение — часы сервера.
