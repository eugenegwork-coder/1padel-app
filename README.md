# 1Padel.App

Самостоятельный проект Expo / React Native. Основа — действующий клиент `/app/` из `UstinKO/padel-core-service`, а не старый прототип из корня этого репозитория. Вход, расписание, личные мероприятия, индивидуальная запись/отмена и парная запись сохранены. Исторические пакеты в `updates/` не применять повторно поверх текущего кода.

## Установка и проверка

Нужны Node.js 24 и pnpm 11.25.0 (версия закреплена в package.json).

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build:all
pnpm preview
```

`pnpm build:web` собирает веб, `pnpm build:all` — пакеты кода web/iOS/Android. Результат только в `dist/` этого проекта. Это ещё не IPA/APK и не публикация в App Store/Google Play. Команда не меняет серверный репозиторий, сайт или пользовательские данные.

`pnpm preview` открывает локальный сервер http://localhost:8081/. Если порт занят: `PORT=8091 pnpm preview`. Предпросмотр доступен только на компьютере. Для Expo Go: `pnpm start` и телефон в той же сети. Google в native пока недоступен.

## Адрес сервера

По умолчанию запросы идут в https://1-padel.com. Чтобы использовать другой сервер, создайте `.env.local` по `.env.example`, укажите `EXPO_PUBLIC_API_BASE_URL=https://your-server.example` и пересоберите приложение. Этот публичный параметр одинаков для входа, расписания, индивидуальной и парной записи. Разрешён только HTTPS-адрес без пути, пароля, query и fragment. Токены тестового сервера хранятся отдельно от production; существующий production-ключ сохранён.

Команды сборки используют переменные окружения и `.env.local`; другие .env-файлы при сборке отключены для воспроизводимости. В эти переменные нельзя помещать секреты. Для размещения в подпапке задайте `PADEL_WEB_BASE_PATH=/app` при сборке; по умолчанию приложение размещается в корне отдельного адреса.

Локальный preview и Metro проксируют только публичный GET расписания. Они не пересылают cookies/токены и не обходят авторизацию для записи. Preview читает адрес API из `dist/build-info.json`, поэтому не смешивает сборку одного сервера с данными другого.

Для отдельного веб-домена сервер должен разрешить его адрес (CORS). В текущей серверной конфигурации разрешены localhost:8081 и несколько адресов сайта, но не произвольный новый домен. На другом порту вход может блокироваться браузером. Настройки сервера в этом этапе не менялись.

## Вход и границы текущего этапа

— Почта/пароль используют существующие `/api/auth/*`. Настоящий вход не проверяется автоматическими тестами на реальном аккаунте.
— Google работает в опубликованном веб-клиенте на адресе сервера; его возврат привязан к `/app/`. В самостоятельном клиенте и native кнопка явно недоступна до подключения отдельного безопасного возврата. Не обещаем, что вход в браузере сайта авторизует отдельное приложение.
— Apple, push, подписанные магазинные сборки и учётные записи публикации ещё не подключены.
— Парная отмена и некоторые действия по приглашениям пока ведут на сайт. Организаторский экран остаётся демонстрационным.
— Правила турниров и изменения дизайна не переписывались при выделении проекта. Новые решения от 28–29 октября нужно сверить с сервером перед переносом.

## Автоматические проверки

GitHub Actions `Check and build app` устанавливает зависимости с lock-файлом, запускает тесты/TypeScript и экспортирует web/iOS/Android. Результат доступен как `app-export`. Workflow не публикует сайт, не вызывает деплой сервера, не отправляет письма и не записывает игроков.
